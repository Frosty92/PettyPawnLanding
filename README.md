## Re-recording

1. Start the app on web: `pettypawn-web-8086` in `.claude/launch.json`.
2. Build the helpers once, outside the project: `swiftc -O capture/encode.swift -o "$SCRATCH/encode"`, and the same for `sheet.swift`.
3. The battle clip: `cd capture && SCRATCH=… ENCODER=$SCRATCH/encode node battle.mjs`; the story clip the same way with `fall.mjs` (`CUT=` sets its end, 13.6 s by default). `DEBUG=1` saves a still at each beat. The old fight is `node demo.mjs`; add `&blood=0` to a Studio path for a clip without blood.
4. The walk-out still: `cd capture && SCRATCH=… node walkout.mjs`. The Board: `node capture/board.mjs "$SCRATCH" /studio-wall assets/screens/board.jpg`. The stolen-pet card as a still: `node capture/pawned.mjs "$SCRATCH" assets/screens/pawned.jpg`.
5. `"$SCRATCH/sheet" "$SCRATCH/fight.txt" out.jpg 0.5` lays a take out as a contact sheet.

`?snap=story|no-chill|most-wanted|get` shows that section at the top of the page, for headless screenshots.

## Deploying

Live at https://pettypawn.com and https://www.pettypawn.com: Cloudflare Pages project `pettypawn-landing` (`pettypawn-landing.pages.dev`), connected to github.com/Frosty92/PettyPawnLanding since 2026-10-27.

- **Pushing to `main` deploys.** Pages checks the repo out, runs `bash build.sh` (which puts the page, its scripts and `assets/` in `site/`) and serves `site/` with `functions/`; `wrangler.toml` at the root binds the D1 database. `capture/`, `brand/`, `migrations/` and this README never leave the repo. Builds take about a minute; Workers & Pages → pettypawn-landing → Deployments shows each one. Other branches build nothing (previews are off). If a push builds nothing, the Cloudflare Workers and Pages GitHub app does not have this repository: GitHub → Settings → Applications → Installed GitHub Apps → Cloudflare Workers and Pages → Configure → Repository access. Until then a build can be started by hand (Deployments → Create deployment, or `POST …/pages/projects/pettypawn-landing/deployments` with the account's token). The project was first made by direct upload, which Cloudflare cannot connect to Git afterwards, so it was deleted and remade with the same name; `deploy.sh` is superseded and kept only for cleanup.
- `wrangler.toml` binds the D1 database `pettypawn-waitlist` as `DB`. A new migration goes in `migrations/` and is applied with `npx wrangler d1 migrations apply pettypawn-waitlist --remote`.
- Read the list: `npx wrangler d1 execute pettypawn-waitlist --remote --command "SELECT * FROM waitlist ORDER BY created_at"`, or Workers & Pages → D1 → pettypawn-waitlist → Console in the dashboard.
- DNS for pettypawn.com (2026-10-27): `@` and `www` are proxied CNAMEs to `pettypawn-landing.pages.dev`; mail goes to Google Workspace (MX `smtp.google.com` priority 1, SPF, DKIM `google._domainkey` and DMARC `v=DMARC1; p=none`), and hello@pettypawn.com works.
- The game server (Worker `maidenless-production`, branch `pettypawn`) answers `pettypawn.com/terms*`, `/privacy*`, `/community*`, `/support*`, `/delete-account*` and `/fr/*` on both hostnames by path routes; the landing page keeps the home page, and its footer links to those pages.
