## Re-recording

1. Start the app on web: `pettypawn-web-8086` in `.claude/launch.json`. For an app already running on another port, set `APP=http://localhost:8081` on the commands below.
2. Build the helpers once, outside the project: `swiftc -O capture/encode.swift -o "$SCRATCH/encode"`, and the same for `sheet.swift`.
3. The hero clip: `cd capture && SCRATCH=… ENCODER=$SCRATCH/encode node battle.mjs` (`CUT=` sets its end, 29.6 s by default); the second clip the same way with `lights.mjs`. `DEBUG=1` saves a still at each beat. Add `&blood=0` to a Studio path for a clip without blood.
4. The Board: from `capture/`, `SCRATCH=… node board.mjs "$SCRATCH" /studio-wall ../assets/screens/board.jpg`.
5. `"$SCRATCH/sheet" "$SCRATCH/fight.txt" out.jpg 0.5` lays a take out as a contact sheet.

`?snap=no-chill|most-wanted|get` shows that section at the top of the page, for headless screenshots.

## Deploying

Live at https://pettypawn.com and https://www.pettypawn.com: Cloudflare Pages project `pettypawn-landing` (`pettypawn-landing.pages.dev`), connected to github.com/Frosty92/PettyPawnLanding since 2026-10-27.

- **Pushing to `main` deploys.** Pages checks the repo out, runs `bash build.sh` (which puts the page, its scripts and `assets/` in `site/`) and serves `site/` with `functions/`; `wrangler.toml` at the root binds the D1 database. `capture/`, `brand/`, `migrations/` and this README never leave the repo. Builds take about a minute; Workers & Pages → pettypawn-landing → Deployments shows each one. Other branches build nothing (previews are off). The founder gave the Cloudflare Workers and Pages GitHub app this repository on 2026-10-28. If a push builds nothing, check that the app still has it: GitHub → Settings → Applications → Installed GitHub Apps → Cloudflare Workers and Pages → Configure → Repository access. Until then a build can be started by hand (Deployments → Create deployment, or `POST https://api.cloudflare.com/client/v4/accounts/916e77e2420e42c7e047acd7e4a7f86e/pages/projects/pettypawn-landing/deployments` with the account's token). The project was first made by direct upload, which Cloudflare cannot connect to Git afterwards, so it was deleted and remade with the same name. The remake through the API showed the repository as connected but never received a push, so on 2026-10-28 it was made a third time from the dashboard (Workers & Pages → Create → Pages → Import an existing Git repository); the D1 binding comes from `wrangler.toml`. Pushes still started no build after that, and GitHub shows no Cloudflare check on them: the pushes are not reaching Cloudflare (see the plan, `PettyPawn/docs/exec-plans/active/2026-10-27_pettypawn-com-waitlist-and-email.md`). `deploy.sh` is superseded and kept only for cleanup.
- `wrangler.toml` binds the D1 database `pettypawn-waitlist` as `DB`. A new migration goes in `migrations/` and is applied with `npx wrangler d1 migrations apply pettypawn-waitlist --remote`.
- Read the list: `npx wrangler d1 execute pettypawn-waitlist --remote --command "SELECT * FROM waitlist ORDER BY created_at"`, or Workers & Pages → D1 → pettypawn-waitlist → Console in the dashboard.
- DNS for pettypawn.com (2026-10-27): `@` and `www` are proxied CNAMEs to `pettypawn-landing.pages.dev`; mail goes to Google Workspace (MX `smtp.google.com` priority 1, SPF, DKIM `google._domainkey` and DMARC `v=DMARC1; p=none`), and hello@pettypawn.com works.
- The game server (Worker `maidenless-production`, branch `pettypawn`) answers `pettypawn.com/terms*`, `/privacy*`, `/community*`, `/support*`, `/delete-account*` and `/fr/*` on both hostnames by path routes; the landing page keeps the home page, and its footer links to those pages.
